pass with an offline GPG primary key on macOS

Nov 18, 2026

How to use pass on macOS with the GPG primary key kept offline. The laptop only holds the encryption and signing subkeys. The primary key can only certify (create and extend subkeys) and lives on an encrypted USB stick.

1. Create the keys in an offline vault

Format a USB stick as APFS (Encrypted) and name it GPGVAULT. Turn off Wi-Fi.

export GNUPGHOME=/Volumes/GPGVAULT/gnupg
mkdir -m 700 "$GNUPGHOME"

# certify-only primary, no expiry
gpg --quick-gen-key "Your Name <you@example.com>" ed25519 cert never
FPR=$(gpg --list-keys --with-colons | awk -F: '/^fpr/{print $10; exit}')

# subkeys, each expiring in 2 years
gpg --quick-add-key "$FPR" cv25519 encr 2y
gpg --quick-add-key "$FPR" ed25519 sign 2y

# backups (revocation cert is auto-created in $GNUPGHOME/openpgp-revocs.d/)
gpg --armor --export-secret-keys    "$FPR" > /Volumes/GPGVAULT/primary-secret.asc
gpg --armor --export                "$FPR" > /Volumes/GPGVAULT/public.asc
gpg --armor --export-secret-subkeys "$FPR" > /Volumes/GPGVAULT/subkeys-secret.asc

Keep a second copy (another USB stick or a paperkey printout).

2. Import only the subkeys on the laptop

unset GNUPGHOME
gpg --import /Volumes/GPGVAULT/public.asc /Volumes/GPGVAULT/subkeys-secret.asc
echo "$FPR:6:" | gpg --import-ownertrust
gpg -K    # must show "sec#": the # means the primary secret is absent

To strip the primary from an existing key instead, find its keygrip with gpg -K --with-keygrip (the first one) and delete ~/.gnupg/private-keys-v1.d/<keygrip>.key.

3. Configure pass with the primary fingerprint

Always use the primary fingerprint. gpg picks the right subkey, so rotating a subkey doesn't break anything. pass's signature check accepts the primary fingerprint as well as the signing subkey's.

# ~/.zshrc
export PASSWORD_STORE_SIGNING_KEY="<FPR>"   # .gpg-id and extensions must be signed
export GPG_TTY=$(tty)

pass init "<FPR>"
pass git init
git -C ~/.password-store config user.signingkey "<FPR>"
git -C ~/.password-store config pass.signcommits true

Without PASSWORD_STORE_SIGNING_KEY, anyone who can write to the store (git remote, cloud sync) can add their key to .gpg-id. New passwords would then also be encrypted to them.

In ~/.gnupg/gpg-agent.conf, use pinentry-mac and a short cache (default-cache-ttl 600, max-cache-ttl 1800).

4. Maintenance (mount vault, offline, export GNUPGHOME=/Volumes/GPGVAULT/gnupg)

  • Extend the expiry: run gpg --quick-set-expire "$FPR" 2y '*', re-export public.asc and import it on the laptop.
  • Rotate the encryption subkey: add a new encr subkey and revoke the old one; don't just let it expire. pass's re-encrypt check counts every non-revoked encryption subkey, expired ones included. Then re-import the subkeys and run pass init "<FPR>" to re-encrypt. Keep the old secret until that's done.

Next step
